# Welcome to Web+

**Web+** (webplus) is a systems-level programming language designed specifically for the web. Inspired by C++, Web+ combines low-level performance and memory control with web-native primitives, compiling directly to WebAssembly for deterministic, high-performance execution.

## Why Web+?

Web+ is **not** a JavaScript replacement for beginners. It's a language for experienced systems and C++ programmers who need:

- **C++-level performance** with manual memory management
- **Web-native primitives** as first-class language features
- **Deterministic execution** without garbage collection
- **Cross-platform** support (browser, server, edge)
- **Zero-cost abstractions** and predictable behavior

## Key Features

<CardGroup cols={2}>
  <Card title="Systems-Level Control" icon="microchip">
    Manual memory management with stack, heap, and arena allocators. Full control over memory layout and execution.
  </Card>
  <Card title="Web-Native Primitives" icon="globe">
    DOM manipulation, HTTP routing, fetch, and workers built directly into the language—not as libraries.
  </Card>
  <Card title="WebAssembly Target" icon="cube">
    Compiles to optimized WebAssembly via LLVM, with minimal JavaScript glue only when needed.
  </Card>
  <Card title="Concurrency Built-In" icon="arrows-split-up-and-left">
    First-class support for Web Workers and concurrent execution with deterministic memory behavior.
  </Card>
</CardGroup>

## Quick Example

```webplus
// Client-side DOM manipulation
void main() {
    dom::Element button = dom::get("#submit");
    button.on("click", [] {
        dom::get("#status").text("Clicked!");
    });
}

// Server-side HTTP routing
route GET "/api/hello" -> Response {
    return json({ "message": "Hello from Web+!" });
}

// Concurrent background task
worker w = worker::spawn([] {
    return fib(40);
});
int result = w.join();
```

## Architecture

Web+ v0.1 uses a transpiler architecture:

1. **Web+ Source** → Parser → AST
2. **AST** → Code Generator → C++
3. **C++** → Emscripten → WebAssembly
4. **WebAssembly** + minimal JS glue → Browser/Server

Future versions will compile directly to WebAssembly via LLVM, eliminating the C++ intermediate step.

## Philosophy

Web+ follows strict design principles:

- **Performance first** — All abstractions are zero-cost or opt-in
- **Explicit over implicit** — Memory and concurrency behavior is visible
- **Web-native, not web-compatible** — Web APIs are language primitives
- **No beginner optimizations** — Designed for experienced developers
- **Determinism matters** — Predictable execution and memory behavior

# Installation

This page provides detailed installation instructions for Web+ and all its dependencies.

## System Requirements

### Supported Platforms

- **Windows** 10/11 (x64)
- **macOS** 11 Big Sur or later
- **Linux** (Ubuntu 20.04+, Fedora 35+, or equivalent)

### Required Software

- **Node.js** v18.0.0 or higher
- **npm** v9.0.0 or higher
- **Emscripten SDK** v3.1.0 or higher
- **Git** (for cloning examples)

## Step 1: Install Node.js

### Windows

Download from [nodejs.org](https://nodejs.org/) and run the installer.

### macOS

Using Homebrew:

```bash
brew install node
```

### Linux

```bash
# Ubuntu/Debian
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# Fedora
sudo dnf install nodejs
```

Verify installation:

```bash
node --version
npm --version
```

## Step 2: Install Emscripten SDK

Emscripten is required to compile C++ to WebAssembly.

### All Platforms

```bash
# Clone the Emscripten repository
git clone https://github.com/emscripten-core/emsdk.git
cd emsdk

# Download and install the latest SDK tools
./emsdk install latest

# Activate the SDK for current user
./emsdk activate latest

# Set up environment variables (required for every session)
source ./emsdk_env.sh
```

### Permanent PATH Setup

#### Windows (PowerShell)

Add to your PowerShell profile:

```powershell
# Edit profile
notepad $PROFILE

# Add this line
& "C:\path\to\emsdk\emsdk_env.ps1"
```

#### macOS/Linux (Bash/Zsh)

Add to `~/.bashrc`, `~/.zshrc`, or `~/.profile`:

```bash
# Add to shell config
echo 'source "/path/to/emsdk/emsdk_env.sh"' >> ~/.bashrc

# Reload shell
source ~/.bashrc
```

### Verify Emscripten

```bash
emcc --version
```

Expected output:

```
emcc (Emscripten gcc/clang-like replacement) 3.1.50 (...)
```

## Step 3: Install Web+

### From Source (Recommended for v0.1)

```bash
# Clone the repository
git clone https://github.com/Solez-ai/webplus.git
cd webplus

# Install dependencies for all workspaces
npm install

# Build all packages
npm run build

# Link CLI globally
cd cli
npm link

# Verify installation
webplus --version
```

### Expected Output

```
Web+ v0.1.0
A C++-inspired systems language for the web
```

## Step 4: Verify Installation

Create a test file `test.webplus`:

```webplus
void main() {
    dom::get("#app").text("Web+ is working!");
}
```

Build it:

```bash
webplus build test.webplus -o test-build
```

If successful, you'll see:

```
✔ Build successful! Output: /path/to/test-build
```

## Optional: Install VS Code Extension

The Web+ VS Code extension provides syntax highlighting, IntelliSense, and debugging.

### Install from Source

```bash
cd webplus/vscode-extension
npm install
npm run build

# Package extension
vsce package

# Install in VS Code
code --install-extension webplus-0.1.0.vsix
```

### Features

- Syntax highlighting for `.webplus` files
- IntelliSense for Web+ keywords and standard library
- Inline error diagnostics
- Code snippets

## Troubleshooting

### Emscripten Installation Issues

**Error: `emcc: command not found`**

Solution: Ensure `emsdk_env.sh` is sourced in your current shell:

```bash
source /path/to/emsdk/emsdk_env.sh
```

**Error: `EMSDK environment variables not set`**

Solution: Re-activate Emscripten:

```bash
cd /path/to/emsdk
./emsdk activate latest
source ./emsdk_env.sh
```

### Web+ Build Issues

**Error: `Cannot find module '@webplus/transpiler'`**

Solution: Ensure dependencies are installed:

```bash
cd webplus
npm install
npm run build
```

**Error: `Permission denied` during `npm link`**

Solution: Use sudo (Linux/macOS) or run as Administrator (Windows):

```bash
sudo npm link
```

### Browser Compatibility

Web+ requires WebAssembly support. Supported browsers:

- **Chrome** 57+
- **Firefox** 52+
- **Safari** 11+
- **Edge** 16+

# Quick Start

This guide will help you install Web+ and build your first application.

## Prerequisites

Before you begin, ensure you have:

- **Node.js** v18 or higher
- **Emscripten SDK** (for WebAssembly compilation)
- A code editor (VS Code recommended)

## Install Emscripten

Web+ v0.1 uses Emscripten to compile C++ to WebAssembly. Install it:

```bash
# Clone Emscripten SDK
git clone https://github.com/emscripten-core/emsdk.git
cd emsdk

# Install and activate latest
./emsdk install latest
./emsdk activate latest

# Add to PATH (add to ~/.bashrc or ~/.zshrc)
source ./emsdk_env.sh
```

Verify installation:

```bash
emcc --version
```

## Install Web+

Install Web+ globally via npm:

```bash
cd webplus
npm install
npm run build

# Link CLI globally
cd cli
npm link
```

Verify installation:

```bash
webplus --version
```

You should see: `web+ v0.1.0`

## Your First Program

Create a new file `hello.webplus`:

```webplus
void main() {
    dom::get("#app").text("Hello, Web+!");
}
```

## Build

Compile your Web+ code to WebAssembly:

```bash
webplus build hello.webplus -o build
```

This will:
1. Transpile Web+ → C++
2. Compile C++ → WebAssembly with Emscripten
3. Generate an HTML runner

## Run

Open `build/index.html` in your browser, or use the dev server:

```bash
webplus serve . --port 3000
```

Navigate to `http://localhost:3000` to see your app running!

## What Just Happened?

1. **Transpilation**: Web+ source was parsed and converted to Emscripten-compatible C++
2. **Compilation**: C++ was compiled to optimized WebAssembly `.wasm` file
3. **Execution**: Your WebAssembly module runs in the browser with minimal JS glue

# Developer Guide

Welcome to the internal development guide for Web+. This page explains how to build the transpiler and CLI from source.

## Repository Structure

- `/transpiler`: The core logic that converts Web+ to C++.
- `/cli`: The command-line tool interface.

1. **Clone the Repo**
   ```bash
   git clone https://github.com/Solez-ai/webplus.git
   cd webplus
   ```

2. **Install Dependencies**
   Web+ uses npm workspaces. Run at the root:
   ```bash
   npm install
   ```

3. **Build Components**
   ```bash
   npm run build
   ```

The transpiler is written in TypeScript.
- **Parser**: Located in `transpiler/src/parser.ts`.
- **Codegen**: Located in `transpiler/src/codegen/`.

```bash
cd cli && npm link
```

```bash
npm run test
```

## Technical Identity
Web+ is a systems-level language compiled to WebAssembly. It uses C++ syntax with built-in web primitives and manual memory management.

## Key Primitives

### DOM Manipulation
```cpp
dom::Element app = dom::get("#app");
app.text("Hello World");
app.on("click", []() { /* handle click */ });
```

### Async & Fetch
```cpp
webplus::fetch("/api/data").then([](Response r) {
    webplus::print("Status: ", r.status());
});
```

### Background Workers
```cpp
worker w = worker::spawn([] { 
    return perform_heavy_task(); 
});
int res = w.join();
```

## Memory Model Summary

- **No Garbage Collection**: All heap memory must be manually freed.
- **Stack**: Automatic local variables.
- **Heap**: `alloc<T>(n)` and `free_ptr(p)`.
- **Arena**: Bulk allocation for temporary tasks.

# Standard Library Reference

The Web+ standard library provides essential runtime features for both browser and server environments. This is the minimal v0.1 implementation focusing on core functionality.

## Philosophy

The Web+ stdlib follows these principles:

- **Zero-cost abstractions** - No overhead from library usage
- **Manual memory management** - Explicit and predictable
- **Web-native** - First-class support for DOM and browser APIs
- **Cross-platform** - Works in browser (via WASM) and server (via WASI)
- **Minimal footprint** - Only include what you use

## Memory Primitives

### Basic Types

```cpp
webplus::int32      // 32-bit signed integer
webplus::float32    // 32-bit floating point
webplus::float64    // 64-bit floating point (double)
webplus::bool_t     // Boolean type
webplus::char_t     // Single character
```

### String

Manual memory-managed UTF-8 string class.

#### Constructor

```cpp
webplus::String str();              // Empty string
webplus::String str("Hello");       // From C-string
webplus::String str2(str);          // Copy constructor
```

#### Methods

```cpp
const char* c_str() const;          // Get C-string pointer
size_t length() const;              // Get string length
bool empty() const;                 // Check if empty
void append(const char* str);       // Append string
void clear();                       // Clear and free memory
```

#### Example

```cpp
webplus::String message = "Hello";
message.append(", World!");
webplus::print(message.c_str());    // Output: Hello, World!
message.clear();                    // Free memory
```

### Memory Allocation

```cpp
template<typename T>
T* alloc(size_t count);             // Allocate count elements

template<typename T>
void free_ptr(T* ptr);              // Free allocated memory
```

#### Example

```cpp
int* numbers = webplus::alloc<int>(10);
numbers[0] = 42;
webplus::free_ptr(numbers);
```

### Stack Arrays

Fixed-size arrays allocated on the stack (or managed heap).

```cpp
template<typename T>
class StackArray<T> {
    explicit StackArray(size_t size);
    T& operator[](size_t index);
    size_t size() const;
    T* data();
};
```

#### Example

```cpp
webplus::StackArray<int> arr(5);
arr[0] = 10;
arr[1] = 20;
```

### Arena Allocator

Fast bump allocator for temporary allocations.

```cpp
template<typename T>
class Arena<T> {
    explicit Arena(size_t capacity);
    T* allocate(size_t count);
    void reset();
    size_t available() const;
};
```

#### Example

```cpp
webplus::Arena<int> arena(1000);
int* temp1 = arena.allocate(5);
int* temp2 = arena.allocate(10);
arena.reset();  // Reset, invalidates all pointers
```

## Containers

### Vector

Dynamic array with automatic growth.

```cpp
template<typename T>
class Vector<T> {
    Vector();
    void push(const T& value);
    T pop();
    T& at(size_t index);
    T& operator[](size_t index);
    size_t size() const;
    size_t capacity() const;
    bool empty() const;
    void clear();
    void reserve(size_t new_capacity);
    T* data();
};
```

#### Example

```cpp
webplus::Vector<int> numbers;
numbers.push(10);
numbers.push(20);
numbers.push(30);

for (size_t i = 0; i < numbers.size(); i++) {
    webplus::print(numbers[i]);
}

int last = numbers.pop();  // 30
numbers.clear();
```

#### Example

### warn()

#### Example


### error()

## DOM Access (Browser Only)

### Element

Represents a DOM element with ID-based tracking.

```cpp
class Element {
    bool is_valid() const;
    void text(const String& value);
    String text() const;
    void html(const String& value);
    void set_attribute(const String& name, const String& value);
    void add_class(const String& className);
    void remove_class(const String& className);
    void append(const Element& child);
    void remove();
};
```

### Functions

```cpp
Element get(const String& selector);
Element createElement(const String& tagName);
Element getElementById(const String& id);
```

#### Example

```cpp
using namespace webplus::dom;

Element app = get("#app");
if (app.is_valid()) {
    app.html("<h1>Hello, Web+!</h1>");
    
    Element button = createElement("button");
    button.text("Click me");
    button.add_class("btn-primary");
    button.set_attribute("id", "myButton");

```

## HTTP Fetch (Browser Only)

### Response

Represents an HTTP response.

```cpp
class Response {
    const String& body() const;
    int status() const;
    bool ok() const;
    String json_string() const;
};
```

### Promise

Promise-like interface for async operations.

```cpp
class Promise {
    template<typename F>
    void then(F callback);
};
```

### fetch()

Make HTTP requests.

```cpp
Promise fetch(const String& url);
Promise fetch(const String& url, const String& method, const String& body);
```

#### Example

```cpp

webplus::Promise response = webplus::fetch(url);

// Note: Full callback support coming in v0.2
// For now, demonstrates the API structure
```

## Runtime Initialization

### Functions

```cpp
namespace webplus {
    void stdlib_init();      // Initialize standard library
    void stdlib_cleanup();   // Cleanup and free resources
}

namespace webplus::wasm {
    void init();             // Initialize WASM runtime
    void cleanup();          // Cleanup WASM runtime
}
```

#### Example

```cpp
void main() {
    webplus::stdlib_init();
    
    // Your application code here

}
```

## Platform Detection

The stdlib automatically detects the target platform:

- `__EMSCRIPTEN__` - Browser/WASM build
- Otherwise - Native/server build

Platform-specific features are conditionally compiled.

## Performance Characteristics

### Memory

- **String**: O(1) access, O(n) append with reallocation
- **Vector**: O(1) push (amortized), O(1) access, O(n) reallocation
- **Arena**: O(1) allocation, O(1) reset

### DOM Operations

- **get/createElement**: O(1) reference tracking
- **text/html**: O(1) via Emscripten JS interop
- **append**: O(1) DOM operation

### Network

- **fetch**: Async, non-blocking in browser

## Limitations (v0.1)

The minimal stdlib has these known limitations:

- ❌ No async callback support (callbacks require C++ function pointers with WASM trampolines)
- ❌ No complete DOM API (only essential operations)
- ❌ No Map/Set containers
- ❌ No file I/O
- ❌ No streams
- ❌ No SQLite bindings

These will be added in v0.2+.

## Memory Safety

The stdlib provides manual memory management. You are responsible for:

1. Freeing allocated memory with `free_ptr()`
2. Not accessing freed memory
3. Not exceeding array bounds
4. Proper lifetime management of objects

Future versions may include optional bounds checking and borrow hints.

## Threading Model

- **Browser**: Single-threaded main execution

# Browser Runtime

The Web+ browser runtime enables Web+ applications to run in modern web browsers via WebAssembly. It provides the bridge between your Web+ code and browser APIs.

## Architecture

```
┌──────────────────────────────────────┐
│   Web+ Application (.webplus)       │
└────────────┬─────────────────────────┘
             │ Transpile
┌────────────▼─────────────────────────┐

└────────────┬─────────────────────────┘
             │ Emscripten
┌────────────▼─────────────────────────┐

             │
┌────────────▼─────────────────────────┐

             │
┌────────────▼─────────────────────────┐
│   Browser APIs (DOM, Fetch, etc.)   │
└──────────────────────────────────────┘
```

## Runtime Lifecycle

### Initialization Sequence

1. Browser loads `index.html`
2. `runtime.js` initializes global registries
3. `main.js` (Emscripten glue) loads
4. `main.wasm` module instantiates
5. `Module.onRuntimeInitialized` fires
6. `runtime_init()` is called
7. Your `main()` function executes

### Cleanup Sequence

1. Page `beforeunload` event fires
2. `runtime_cleanup()` is called
3. Active workers are terminated
4. Registries are cleared
5. WASM module deallocates

## DOM Integration

### Element Tracking

```cpp
// C++ → JS

char* jsString = (char*)EM_ASM_INT({
    const str = "Hello from JS";
    const len = lengthBytesUTF8(str) + 1;
    const ptr = _malloc(len);
    stringToUTF8(str, ptr, len);
    return ptr;
});
```

# Web+ Language Specification v0.1

Web+ is a C++-inspired, systems-level language designed specifically for the web. It compiles to WebAssembly and provides low-level control with web-native primitives.

## Design Philosophy

Web+ follows these core principles:

1. **Performance First** - All abstractions are zero-cost or explicitly opt-in
2. **Explicit Over Implicit** - Memory, concurrency, and async behavior is visible
3. **Web-Native** - DOM, HTTP, workers are language primitives, not libraries
4. **No Beginner Optimizations** - Designed for experienced systems programmers
5. **Determinism Matters** - Predictable execution and memory behavior

## Syntax Overview

Web+ uses C++-style syntax with web-specific extensions:

```webplus
// Comments use C++ style
// This is a single-line comment

/* 
   This is a multi-line comment
*/

// Primitive types
int x = 42;
float pi = 3.14;
double precise = 3.141592653589793;
bool isReady = true;
char c = 'A';
string name = "Web+";

// Pointers and references
int* ptr = alloc<int>(1);
int& ref = *ptr;

// Structs
struct Point {
    float x;
    float y;
};

// Functions
int add(int a, int b) {
    return a + b;
}

// Web primitives
dom::Element elem = dom::get("#app");
worker w = worker::spawn([] { return fib(40); });

// HTTP routes (server-side)
route GET "/api/data" -> Response {
    return json({ "status": "ok" });
}
```

### Integer Types

**Range:** -2,147,483,648 to 2,147,483,647  
**Size:** 4 bytes  
**Alignment:** 4 bytes

### Floating Point Types

```webplus
double d = 3.14159;    // 64-bit floating point
```

**float:**
- Size: 4 bytes
- Precision: ~7 decimal digits
- IEEE 754 single precision

**double:**
- Size: 8 bytes
- Precision: ~15 decimal digits
- IEEE 754 double precision

### Boolean Type

```webplus

bool isClosed = false;
```

**Size:** 1 byte  
**Values:** `true` or `false`

### Character Type


**Size:** 1 byte  
**Encoding:** ASCII

### String Type

### Void Type

```webplus
    // Function returns nothing
```

## Memory Model

Web+ provides explicit memory control without garbage collection.

### Stack Allocation

```webplus
int localVar = 42;           // Stack allocated
Point p = { 10.0, 20.0 };    // Stack allocated struct
```

Stack memory:
- **Automatically managed** within function scope
- **Fast allocation** and deallocation
- **Limited size** (typically few MB)
- **Lifetime:** Until function returns

### Heap Allocation

```webplus
int* heapInt = alloc<int>(1);
heapInt[0] = 42;
free(heapInt);  // Manual deallocation required
```

Heap memory:
- **Manual management** required
- **Unlimited size** (limited by system RAM)
- **Slower** than stack
- **Lifetime:** Until explicitly freed

### Arena Allocation

```webplus
int* arenaInt = arena<int>(100);  // Fast arena allocation
// No individual free - arena cleared as a whole
```

Arena allocators:
- **Fastest allocation** for bulk allocations
- **No individual free**
- **Region-based** memory management
- **Use case:** Temporary buffers, batch processing

## Type System

### Static Typing

Web+ is **statically typed**. All types are checked at compile time:

```webplus
int x = 42;       // OK
x = "string";     // ERROR: type mismatch
```

### Type Inference

Limited type inference in some contexts:

```webplus

```

### Type Conversions

**Implicit conversions** are **not allowed**. All conversions must be explicit:

```webplus
float f = 3.14;
int i = (int)f;       // Explicit cast required
```

### Allowed explicit casts:

- `int` ↔ `float`, `double`
- `char` → `int`
- `bool` → `int` (true=1, false=0)
- Pointers of same base type

### Forbidden conversions:

- `string` ↔ numeric types (use parsing functions)
- Pointers of different base types (without explicit cast)
- `void*` to typed pointer (unsafe)

## Compile-Time Evaluation

Web+ performs several compile-time checks:

### Type Checking

All types must match:

```webplus
int x = 42;
string y = x;  // ERROR: Cannot assign int to string
```

### Memory Safety Hints

Optional bounds checking in debug builds:

```webplus
int* arr = alloc<int>(10);
arr[100] = 42;  // WARNING: Possible out-of-bounds access
```

### Syntax Validation

All syntax must be correct:

```webplus
if (x > 0  // ERROR: Missing closing parenthesis
```

## Execution Model

### Deterministic Execution

Web+ guarantees deterministic execution order:

1. Global variable initialization (if any)
2. `main()` function execution
3. Event callbacks (DOM, HTTP, workers)

### No Garbage Collection

Memory is **never** automatically reclaimed. All allocations must be explicitly freed:

```webplus
int* data = alloc<int>(100);
// ... use data ...
free(data);  // Required!
```

### WebAssembly Runtime

Web+ compiles to WebAssembly, which provides:

- **Sandboxed execution** in browser
- **Near-native performance**
- **Linear memory** model
- **No access** to host system without explicit bindings

**Dangling pointer detection (debug mode):**
```webplus
int* ptr = alloc<int>(1);
free(ptr);
*ptr = 42;  // WARNING: Use after free
```

### Null Safety

**No automatic null checks:**
```webplus
int* ptr = nullptr;
*ptr = 42;  // Undefined behavior, no automatic check
```

**Manual check required:**
```webplus
if (ptr != nullptr) {
    *ptr = 42;
}
```

---

## Best Practices

1. **Use the smallest type** that fits your data
2. **Prefer references** over pointers for function parameters
3. **Avoid void\*** unless absolutely necessary
4. **Always initialize** variables
5. **Use structs** to group related data
6. **Be explicit** - no implicit conversions

# Memory Management

Web+ is designed for performance and predictability. It provides a C++-inspired manual memory model, giving you full control over when and where memory is allocated and freed. There is **no garbage collector** in Web+.

## The Linear Memory Model

In the WebAssembly environment, all Web+ memory resides in a single, large buffer called **Linear Memory**. The runtime organizes this memory into several regions:

1. **Stack**: Used for local variables and function call frames.
2. **Heap**: Used for dynamic allocations via `alloc`.
3. **Data**: Stores global constants and static data.

---

## Stack Allocation

Stack allocation is automatic and handled by the compiler.

```cpp
void calculate() {
    int x = 42;           // Allocated on stack
    float arr[10];        // Allocated on stack
    Point p = { 1, 2 };   // Allocated on stack
} // All memory is automatically reclaimed here
```

- **Pros**: Extremely fast (O(1)), no manual cleanup.
- **Cons**: Limited size, memory is lost when the function returns.

---

## Heap Allocation

Dynamic memory is allocated using `webplus::alloc<T>(count)`. You are responsible for freeing this memory.

```cpp
// Allocate an array of 100 integers
int* buffer = webplus::alloc<int>(100);

// Use the buffer
buffer[0] = 500;

// MUST free to avoid memory leaks
webplus::free_ptr(buffer);
```

### Safety Rules
- **Double Free**: Never call `free_ptr` on the same pointer twice.
- **Memory Leak**: Always ensure every `alloc` has a corresponding `free_ptr`.
- **Dangling Pointer**: Do not use a pointer after it has been freed.

---

## Arena Allocation

Arenas provide a way to perform many small allocations very quickly and free them all in a single operation.

```cpp
// Create an arena with 1MB of space
webplus::Arena<char> tempPool(1024 * 1024);

// Allocate many small objects
char* s1 = tempPool.allocate(10);
char* s2 = tempPool.allocate(20);

// Free EVERYTHING at once
tempPool.reset();
```

Arenas are ideal for tasks with a clear "end of life", such as processing a single HTTP request or a single frame in a game.

---

## Strings and Memory

`webplus::String` is a wrapper around a heap-allocated char buffer.

```cpp
webplus::String s = "Hello";
s.append(" World");

// Strings must be cleared to free their internal heap buffer
s.clear();
```

---

## Memory Safety Features

While Web+ is a low-level language, the compiler provides hints to help you stay safe:

- **Uninitialized Warning**: The compiler warns if you use a variable before assigning it a value.
- **Bounds Checking (Debug Only)**: In development builds (`webplus build --debug`), the runtime will throw an error if you access an array out of its allocated bounds.
- **Null Checks**: You should explicitly check for `nullptr` when dealing with pointers returned from `get()` or `alloc()`.

---

## Best Practices

1. **Prefer Stack over Heap**: Only used `alloc` when the data size is dynamic or needs to outlive the current function.
2. **RAII (Resource Acquisition Is Initialization)**: Wrap pointers in structs that free the memory in their destructor (once Web+ fully supports destructors in v0.2).
3. **Use the Arena**: For any task requiring multiple temporary allocations, use an `Arena` to simplify cleanup and improve performance.

# Concurrency

Web+ provides first-class support for multi-threading via Web Workers. Unlike JavaScript's complex `MessagePort` system, Web+ simplifies concurrency with a C++-inspired model using `worker::spawn` and `join()`.

## Threading Model

Web+ threads (Workers) have the following characteristics:
- **Dedicated Memory**: Each worker runs in its own thread with its own stack and specific heap segments.
- **Asynchronous Execution**: Workers do not block the main UI thread.
- **Deterministic**: Execution order within a worker is strictly linear.

## worker::spawn

The `worker::spawn` primitive creates and starts a new worker.

```webplus
worker w = worker::spawn([] {
    // This code runs in a background thread
    return heavyCalculation();
});
```

### Passing Data
Shared data should be managed carefully. For v0.1, it is recommended to pass data via heap-allocated pointers, ensuring that only one thread accesses the data at a time to avoid race conditions.

---

## Joining Workers

To retrieve the result of a worker, use the `join()` method. This will block the calling thread until the worker has finished its task.

```webplus
worker w = worker::spawn([] {
    return fib(40);
});

// Main thread waits here
int result = w.join();
webplus::print("Result: ", result);
```

> **Warning**: Calling `join()` on the main thread will block the browser UI. For long-running tasks, consider using callbacks or polling if you need to keep the UI responsive.

---

## Detaching Workers

If you don't need the result of a worker, you can `detach()` it. The worker will continue to run in the background, and its resources will be reclaimed by the runtime upon completion.

```webplus
worker w = worker::spawn([] {
    saveDataToDisk();
});

w.detach();
// Main thread continues immediately
```

---

## Example: Parallel Processing

```webplus
int processTask(int id) {
    // Complex logic...
    return id * 2;
}

void main() {
    webplus::Vector<worker> tasks;
    
    // Spawn 4 parallel tasks
    for (int i = 0; i < 4; i++) {
        tasks.push(worker::spawn([i] {
            return processTask(i);
        }));
    }
    
    // Collect results
    for (int i = 0; i < 4; i++) {
        int res = tasks[i].join();
        webplus::print("Task ", i, " result: ", res);
    }
}
```

---

## Limitations in v0.1

- **No SharedArrayBuffer**: v0.1 doesn't support shared memory between workers yet.
- **Single-wait**: You can only `join()` a worker once.
- **Manual Cleanup**: Ensure your worker code cleans up its own heap allocations.

# Memory API

Web+ is a systems-oriented language that provides explicit control over memory. This section details the core primitives and allocation patterns.

## Primitive Types

The standard library defines fixed-width and primitive types in the `webplus` namespace:

```cpp
webplus::int32      // 32-bit signed integer
webplus::float32    // 32-bit single-precision float
webplus::float64    // 64-bit double-precision float
webplus::bool_t     // Boolean (true/false)
webplus::char_t     // Single ASCII character
```

## Heap Allocation

Use the `alloc` template function to allocate memory on the heap. You MUST manually free this memory using `free_ptr`.

### alloc\<T\>

Allocates a block of memory sufficient to hold `count` elements of type `T`.

```cpp
template<typename T>
T* alloc(size_t count);
```

**Parameters:**
- `count`: Number of elements to allocate.

**Returns:**
- A pointer to the newly allocated memory.

### free_ptr\<T\>

Deallocates memory previously allocated with `alloc`.

```cpp
template<typename T>
void free_ptr(T* ptr);
```

**Parameters:**
- `ptr`: Pointer to the memory block to be freed.

---

## String Class

`webplus::String` is a manual-memory managed UTF-8 string.

### Usage

```cpp
// Creation
webplus::String name = "Web+";

// Operations
name.append(" is fast");
size_t len = name.length();
const char* raw = name.c_str();

// Cleanup
name.clear(); // Explicitly free the buffer
```

### Methods
- `c_str()`: Returns a pointer to the null-terminated C-string.
- `length()`: Returns the number of characters.
- `empty()`: Returns true if the string is empty.
- `append(const char*)`: Appends text to the string.
- `clear()`: Frees the internal buffer.

---

## Arena Allocator

The `Arena` allocator provides fast "bump" allocation for short-lived data. All memory is freed at once when the arena is reset.

### Definition

```cpp
webplus::Arena<int> arena(1024); // 1024 elements
int* data = arena.allocate(10);  // O(1) allocation
arena.reset();                    // O(1) bulk free
```

**Best for:**
- Temporary processing buffers
- Per-frame request allocations
- Batch processing

---

## StackArray\<T\>

A thin wrapper around stack-allocated (fixed-size) arrays with safety checks.

```cpp
webplus::StackArray<int> arr(10);
arr[0] = 5;
size_t s = arr.size();
```

**Note:** Sizes must be known or fixed at allocation time.

---

## Best Practices

1. **RAII-like clearing**: Always pair an allocation or string creation with an explicit `clear()` or `free_ptr()`.
2. **Use Arenas for Temp Data**: Avoid heap fragmentation by using `Arena` for tasks that only need memory for a short duration.
3. **Null Check**: Always verify the validity of elective pointers before dereferencing.

# Containers

Web+ provides highly optimized, manual-memory managed containers for dynamic data storage.

## Vector\<T\>

The `Vector` is a dynamic array that grows automatically as you add elements. It is the primary container for most applications.

### Definition

```cpp
#include "runtime/vector.hpp"

webplus::Vector<int> list;
```

### Methods

#### list.push(value)
Adds an element to the end of the vector. If the capacity is exceeded, the vector will automatically reallocate with more space.
- **Complexity**: Amortized O(1)

#### list.pop()
Removes and returns the last element.
- **Complexity**: O(1)

#### list.at(index) / list[index]
Accesses the element at the specified index.
- **Complexity**: O(1)

#### list.size()
Returns the number of elements currently in the vector.

#### list.capacity()
Returns the total number of elements the vector can hold before the next reallocation.

#### list.clear()
Frees the underlying buffer and resets the size to 0.

#### list.reserve(new_capacity)
Increases the capacity of the vector to at least `new_capacity`.

### Example

```cpp
webplus::Vector<webplus::String> names;

names.push("Alice");
names.push("Bob");

for(size_t i = 0; i < names.size(); i++) {
    webplus::print("Person: ", names[i].c_str());
}

// Cleanup
names.clear();
```

---

## Performance Considerations

- **Manual Management**: Unlike JavaScript Arrays, `webplus::Vector` does not have a hidden garbage collector. You must call `clear()` when the vector is no longer needed.
- **Contiguous Memory**: Elements are stored in contiguous memory, making `at()` extremely fast and cache-friendly.
- **Reallocation**: To avoid frequent reallocations, use `reserve()` if you know the approximate number of elements you'll be storing.

# Fetch API

The Fetch API allows Web+ applications to make network requests to servers.

## Functions

### fetch(url)
Makes a simple HTTP `GET` request.
- **Returns**: `webplus::Promise`

### fetch(url, method, body)
Makes an HTTP request with a specific method and payload.
- **Returns**: `webplus::Promise`

---

## Response Class

The `Response` object is returned once the fetch promise resolves.

### Methods
- `ok()`: Returns true if the status is in the 200-299 range.
- `status()`: Returns the HTTP status code.
- `body()`: Returns the raw response body as a `webplus::String`.
- `json_string()`: A convenience method to extract the body for JSON parsing.

---

## Promise Class

Web+ uses a specialized `Promise` class to handle the asynchronous nature of web requests.

### Usage

```cpp
webplus::Promise p = webplus::fetch("https://api.example.com/status");

// Use the then() method to handle the result
p.then([](webplus::Response res) {
    if (res.ok()) {
        webplus::print("Response: ", res.body().c_str());
    }
});
```

> **Note**: In v0.1, the full callback trampoline for `then()` is in a preview state. Native C++ lambdas with captures might have limitations until v0.2.

---

## Example: POSTing Data

```cpp
webplus::String url = "/api/v1/log";
webplus::String payload = "{ \"event\": \"app_start\" }";

webplus::fetch(url, "POST", payload).then([](webplus::Response res) {
    webplus::print("Log sent. Status: ", res.status());
});
```

```cpp
route GET "/user/:id" -> Response {
```

Calculates and returns a `404 Not Found` response.

```cpp
struct Version {

route GET "/version" -> Response {
```

# Workers API

The Workers API provides tools for offloading heavy computations to background threads.

## Types

### worker
A handle to a background worker thread.

## Functions

### worker::spawn(callback)
Spawns a new worker thread and executes the provided function.
- **Returns**: `worker`

### worker.join()
Synchronously waits for the worker to finish and returns its result.
- **Complexity**: Blocks until completion.

### worker.detach()
Allows the worker to run independently. The main thread will not wait for it.

---

## Example: Background Calculation

```cpp
int heavyWork() {
    int sum = 0;
    for(int i = 0; i < 1000000; i++) sum += i;
    return sum;
}

void main() {
    worker w = worker::spawn(heavyWork);
    
    // Do other things...
    
    int result = w.join();
    webplus::print("Sum: ", result);
}
```

---

## Best Practices

- **Avoid frequent spawning**: Spawning a worker has some overhead. Use workers for substantial tasks.
- **Data Isolation**: Workers do not share stack variables. Pass data through heap pointers or shared structures.
- **UI Responsiveness**: Use workers for anything that takes more than 16ms to ensure your app stays at 60fps.

# Building Applications

The `build` command is what turns your human-readable Web+ code into high-performance machine code (WebAssembly). 

## Basic Build

To build a project whose entry point is `main.webplus`:

```bash
webplus build main.webplus
```

This will create a `build/` folder containing:
- `main.wasm`: The compiled binary.
- `main.js`: The JavaScript bridge that interacts with the browser APIs.
- `index.html`: A minimal runner that loads the WASM module.

---

## Production Builds

When you're ready to deploy, you should use the `--optimize` flag.

```bash
webplus build src/main.webplus --optimize --output dist
```

### What `--optimize` does:
1.  **LTO (Link Time Optimization)**: Optimizes the code across multiple files.
2.  **Size Reduction**: Strips out unused standard library functions.
3.  **Instruction Optimization**: Uses LLVM's O3 level to generate the most efficient WASM instructions possible.

---

## Detailed Options Reference

| Option | Description |
| :--- | :--- |
| `-o, --output` | Custom output path. If the directory doesn't exist, it will be created. |
| `--optimize` | Highly recommended for production. Significantly reduces file size and increases speed. |
| `--debug` | Keeps source maps and enables `assert()` statements and bounds checking. |
| `--target` | Set to `browser` (default) for web apps or `server` for WASI-based server apps. |
| `--emcc-flags` | Pass raw flags directly to the underlying Emscripten compiler. |

---

## The Build Pipeline

Understanding the pipeline helps in debugging complex build failures:

1.  **Transpilation**: The CLI reads your `.webplus` files and converts them into C++ source code. You can see this intermediate code in the output directory if you use the `--verbose` flag.
2.  **Inclusion**: The CLI injects the necessary parts of the Web+ Standard Library (located in `stdlib/`).
3.  **WASM Mapping**: High-level primitives like `worker` and `route` are mapped to their low-level C++/JS implementations.
4.  **Emscripten Invocation**: Finally, the CLI invokes `emcc` to generate the final binary artifacts.

---

## Best Practices

### Multimodal Builds
For larger projects, don't build every file every time. Organize your code into modules and use a `webplus.config.json` to define build targets:

```json
{
  "entry": "src/main.webplus",
  "output": "dist",
  "optimize": true,
  "target": "browser"
}
```

### Debugging with `--debug`
Always use `--debug` during development. It ensures that if your code tries to access an array out of bounds or dereference a null pointer, the WASM runtime will provide a readable stack trace in the browser console instead of simply crashing.

# Development Server

The `serve` command is designed to provide a "live" development experience. It combines a static file server with an automated rebuild engine.

## Quick Start

```bash
webplus serve src --open
```

This command will:
1.  Scan the `src` directory for `.webplus` files.
2.  Start a local web server at `http://localhost:3000`.
3.  Automatically open your browser to that address.

---

## How Hot-Reloading Works

The Web+ dev server uses a high-efficiency file watcher:

1.  **Watch**: It monitors every file in your project directory.
2.  **Trigger**: When a `.webplus` file is saved, it immediately triggers a background `build`.
3.  **Halt & Sync**: The browser receives a signal via WebSocket to reload. 
4.  **Refresh**: The browser refreshes, loading the newly compiled `.wasm` binary.

This cycle typically happens in under **500ms**, allowing for nearly instantaneous UI feedback.

---

## Configuration Options

| Flag | Description | Default |
| :--- | :--- | :--- |
| `-p, --port` | The port for the HTTP server. | `3000` |
| `--open` | Automatically open the browser. | `false` |
| `--dir` | The directory to serve files from. | Current |
| `--watch` | Comma-separated list of extra directories to watch. | `src` |

---

## Advanced Usage

### Customizing Ports
If port 3000 is occupied, you can easily shift:

```bash
webplus serve . --port 8080
```

### Serving Multiple Projects
You can run multiple instances of the server by assigning different ports:

```bash
# Terminal 1
webplus serve project_a --port 3001

# Terminal 2
webplus serve project_b --port 3002
```

---

## Troubleshooting

### "Port already in use"
This happens if another server is running. Use `-p` to choose a new port or close the existing server.

### "WASM not loading"
Ensure you are using `webplus serve` instead of opening the `index.html` file directly in your browser. Browsers block WebAssembly loading from `file://` URLs due to security restrictions (CORS).

### Files not updating
Ensure the directory you are "serving" is the same directory where your `build` command is outputting its artifacts, or simply use `webplus serve src` which handles the build-serve loop internally.

# Compiler Architecture

The Web+ compiler is currently a **transpiler-based system** (v0.1) designed for rapid development and compatibility with the existing Emscripten ecosystem.

## Compilation Pipeline

The compilation process consists of four main stages:

### 1. Lexical Analysis & Parsing
- **Input**: `.webplus` source files.
- **Process**: The parser tokenizes the source and builds an Abstract Syntax Tree (AST).
- **Tooling**: Built in TypeScript for the node-based CLI.

### 2. AST Transformation
- The AST is analyzed for type safety and semantic correctness.
- Web-native primitives (like `route` and `worker`) are expanded into internal representations.

### 3. C++ Code Generation
- The AST is converted into highly optimized, Emscripten-compatible C++17 code.
- **Header Injection**: Necessary standard library headers and runtime glue are automatically included.

### 4. Emscripten Compilation
- **Process**: The generated C++ is piped into `emcc`.
- **Output**: Binary WebAssembly (`.wasm`), JavaScript glue (`.js`), and optionally an HTML runner.

---

## The Runtime Bridge

Web+ uses a specialized bridge to communicate between the WASM linear memory and the JavaScript environment.

- **ID Tracking**: DOM elements and Promises are assigned IDs to avoid pointer corruption across the boundary.
- **Trampolines**: C++ callbacks are wrapped in WASM trampolines to allow JS events to trigger Web+ code.

---

## Roadmap: Native LLVM Backend

In future versions (v0.2+), the intermediate C++ step will be removed. The Web+ compiler will target **LLVM IR** directly, allowing for:
- Faster compilation times.
- Better optimization of web-specific primitives.
- Smaller binary sizes without C++ runtime overhead.

# Hello World Tutorial

In this tutorial, we will create a simple "Hello World" application that demonstrates the core workflow of Web+ and basic DOM manipulation.

## 1. Create your source file

Create a new directory for your project and create a file named `main.webplus`:

```webplus
// Web+ Hello World
void main() {
    // 1. Get a handle to the DOM element with id "app"
    dom::Element app = dom::get("#app");
    
    // 2. Set its text content
    app.text("Hello, Web+! This is running in WebAssembly.");
}
```

## 2. Prepare an HTML entry point

Web+ needs an HTML file to host the WebAssembly module. While the `build` command can generate one, let's create a custom `index.html` to understand how it works:

```html
<!DOCTYPE html>
<html>
<head>
    <title>My First Web+ App</title>
</head>
<body>
    <div id="app">Loading...</div>
    <!-- The compiled JS glue will be named main.js by default -->
    <script src="main.js"></script>
</body>
</html>
```

## 3. Build the project

Open your terminal and run the build command:

```bash
webplus build main.webplus -o build
```

The CLI will:
1.  Verify your Web+ syntax.
2.  Transpile and compile your code.
3.  Output `main.js` and `main.wasm` into the `build/` folder.

## 4. Run it!

Start the development server to see your application in action:

```bash
webplus serve build --open
```

You should see "**Hello, Web+! This is running in WebAssembly.**" replacing the "Loading..." text on your screen.

# DOM Manipulation Tutorial

Web+ makes it easy to build dynamic interfaces by providing a type-safe interface for the browser's Document Object Model (DOM).

## Dynamic Element Creation

Instead of hardcoding every HTML element, you can create them on the fly:

```webplus
void main() {
    dom::Element container = dom::get("#app");
    
    // Create a new heading
    dom::Element header = dom::createElement("h1");
    header.text("Interactive Dashboard");
    
    // Append it to our container
    container.append(header);
}
```

---

## Styling and Classes

You can modify an element's appearance by adding or removing CSS classes:

```webplus
void main() {
    dom::Element banner = dom::get(".banner");
    
    // Toggle a class
    if (banner.has_class("hidden")) {
        banner.remove_class("hidden");
        banner.add_class("visible");
    }
    
    // Set direct style attributes
    banner.set_attribute("style", "color: #22d3ee;");
}
```

---

## Event Handling

Interactivity is driven by events. Web+ supports the `on()` method for binding functions to element events:

```webplus
void main() {
    dom::Element btn = dom::get("#click-me");
    
    // Handle a click event using a lambda function
    btn.on("click", [] {
        webplus::print("Button was clicked!");
        dom::get("#output").text("Action completed.");
    });
}
```

---

## Building a Dynamic List

Let's combine these concepts into a practical example:

```webplus
void main() {
    dom::Element app = dom::get("#app");
    dom::Element list = dom::createElement("ul");
    
    // Create items dynamically
    for (int i = 1; i <= 5; i++) {
        dom::Element item = dom::createElement("li");
        item.text("List Item #" + toString(i));
        
        // Add some styling based on index
        if (i % 2 == 0) {
            item.add_class("even-item");
        }
        
        list.append(item);
    }
    
    app.append(list);
}
```

---

## Performance Considerations

### JS Bridge Overhead
Every call to `dom::get` or `dom::createElement` involves a small amount of overhead as the WASM runtime communicates with the browser's JavaScript engine. 

**Tip**: Cache your element handles instead of re-getting them inside a loop:

```webplus
// POOR PERFORMANCE
for(int i = 0; i < 100; i++) {
    dom::get("#output").text(toString(i));
}

// OPTIMIZED PERFORMANCE
dom::Element output = dom::get("#output");
for(int i = 0; i < 100; i++) {
    output.text(toString(i));
}
```

# Concurrency Tutorial

WebAssembly allows for multi-threaded execution in the browser via Web Workers. Web+ abstracts this complexity into a simple `worker` primitive.

## Why use Workers?

The browser's main thread handles both the UI and JavaScript execution. If you run a heavy calculation on the main thread, the entire page will freeze. Workers let you run these tasks in the background, keeping the UI responsive.

## 1. Defining a Background Task

In this tutorial, we'll calculate a large Fibonacci number. Because the recursive implementation is computationally expensive, it's a perfect candidate for a worker.

```webplus
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}
```

---

## 2. Spawning the Worker

Use `worker::spawn` and pass a lambda function containing the code you want to run:

```webplus
void main() {
    dom::Element status = dom::get("#status");
    status.text("Starting calculation...");

    // Start the worker
    worker w = worker::spawn([] {
        int res = fib(42);
        return res;
    });
}
```

---

## 3. Retaining the Result

To get the result back from the worker, use the `join()` method. This will wait for the thread to complete and return the value:

```webplus
void main() {
    worker w = worker::spawn([] { return fib(42); });

    // Wait and get the result
    int finalResult = w.join();
    
    dom::get("#output").text("The answer is: " + toString(finalResult));
}
```

---

## 4. Parallel Workers

You can even run multiple workers at once to utilize multiple CPU cores:

```webplus
void main() {
    worker w1 = worker::spawn([] { return fib(35); });
    worker w2 = worker::spawn([] { return fib(36); });

    // Both are running in parallel now
    int r1 = w1.join();
    int r2 = w2.join();
    
    webplus::print("Sum of tasks: ", r1 + r2);
}
```

---

## Best Practices

### Blocking vs. Non-blocking
The `join()` method is **blocking**. If you call `join()` on the main thread, the UI will still freeze until the worker is done.

**Tip**: For high-performance UIs, consider using a messaging pattern (coming in v0.2) or only `join()` when you are absolutely sure the worker has finished (via polling or event callbacks).

### Memory Safety
Remember that variables declared inside a worker are private to that thread. If you need to share large amounts of data, use heap-allocated pointers, but be careful of race conditions!

# Memory Management Tutorial

One of the most powerful features of Web+ is explicit memory control. Unlike JavaScript, which uses a garbage collector, Web+ lets you decide exactly when memory is used and when it is released.

## 1. Stack Allocation (Automatic)

Most variables you create inside a function are stored on the **Stack**. This memory is automatically managed for you.

```webplus
void process() {
    int x = 100;         // Stack allocated
    float buffer[10];    // Stack allocated
    
    // x and buffer are automatically destroyed when 'process' ends
}
```

---

## 2. Heap Allocation (Manual)

If you need data to persist beyond the current function, or if you don't know the size of the data until runtime, you must use the **Heap**.

Use the `webplus::alloc<T>(count)` function to reserve memory.

```webplus
void main() {
    // 1. Allocate space for 100 integers
    int* data = webplus::alloc<int>(100);
    
    // 2. Use the memory
    data[0] = 5;
    data[99] = 10;
    
    // 3. YOU MUST release the memory!
    webplus::free_ptr(data);
}
```

---

## 3. The Lifecycle of a String

Strings in Web+ are heap-allocated objects. You must explicitly clear them if you create them dynamically.

```webplus
void main() {
    webplus::String name = "Web+ Build";
    name.append(" v0.1");
    
    webplus::print(name.c_str());
    
    // Release the internal buffer
    name.clear();
}
```

---

## 4. Advanced: Using an Arena

If your application needs to make many small, short-lived allocations (for example, during a single draw frame in a game), using individual `alloc`/`free` calls can be slow. An **Arena** solves this by letting you free everything at once.

```webplus
void run_frame() {
    // Create an arena for this frame
    webplus::Arena<char> frameArena(1024 * 10); // 10KB
    
    // Allocate small buffers
    char* temp1 = frameArena.allocate(100);
    char* temp2 = frameArena.allocate(250);
    
    // Process...
    
    // No need to free individual pointers. 
    // All memory is reclaimed when frameArena goes out of scope or is reset().
}
```

---

## The Golden Rules of Memory

1.  **Every `alloc` needs a `free_ptr`**: Forgetting to free memory creates a "Memory Leak," which can eventually crash the user's browser tab.
2.  **Never use a pointer after calling `free_ptr`**: This is called a "Dangling Pointer" and results in undefined behavior.
3.  **Prefer the Stack**: Whenever possible, use local stack variables. They are faster and safer.
4.  **Use `--debug`**: Always build with the `--debug` flag during development. It enables a specialized runtime that will warn you about bounds violations or invalid memory access.

```bash
webplus build main.webplus --debug
```

# Server API Tutorial

Web+ isn't just for the browser. With the `route` primitive, you can build high-performance microservices and APIs that run on WASI-compatible servers.

## 1. Defining a Simple Route

A route handles a specific HTTP method and path. Let's create a basic health-check endpoint:

```webplus
route GET "/health" -> Response {
    return json({ "status": "online", "version": "v0.1" });
}
```

---

## 2. Using URL Parameters

Standard APIs often need to extract IDs from the URL. In Web+, you use the `:` prefix in the path and the `param()` function to extract the value.

```webplus
route GET "/api/user/:id" -> Response {
    // Extract ID (comes in as an int by default)
    int userId = param("id");
    
    // Return a structured response
    return json({ 
        "id": userId,
        "username": "developer_99" 
    });
}
```

---

## 3. Returning Structs as JSON

Web+ makes it easy to serialize complex data structures. Simply define a `struct` and pass a pointer to it into the `json()` function:

```webplus
struct Project {
    int id;
    string title;
    bool isActive;
};

route GET "/api/project" -> Response {
    // 1. Allocate a struct on the heap
    Project* p = alloc<Project>(1);
    
    // 2. Set values
    p->id = 505;
    p->title = "Nebula Engine";
    p->isActive = true;
    
    // 3. Serialized into a JSON Response
    Response res = json(p);
    
    // 4. CLEANUP (Always free heap memory!)
    free(p);
    
    return res;
}
```

---

## 4. Handling POST Requests

For creating or updating data, use the `POST` method:

```webplus
route POST "/api/submit" -> Response {
    // In v0.1, you can access the raw request body via request::body()
    // Validation logic goes here...
    
    return json({ "success": true });
}
```

---

## 5. Deployment

To compile your code for a server environment, you must use the `--target server` flag:

```bash
webplus build main.webplus --target server -o build
```

This will generate a `.wasm` file optimized for runtimes like **Wasmtime** or **Wasmer**. You can run it locally with:

```bash
webplus run build --server
```

---

## Key Terms

- **Route**: A mapping between a URL path and a block of code.
- **Response**: The object returned by a route, containing headers, status code, and body.
- **JSON Serialization**: The process of turning Web+ structs into text strings that other languages (like JS or Python) can understand.
